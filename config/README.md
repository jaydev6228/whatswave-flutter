# Local run configuration

This app is configured entirely through Dart's compile-time environment
(`--dart-define`) — no `.env` file or package is needed, since Flutter has a
built-in equivalent: `--dart-define-from-file`, which reads a flat JSON file
of key/value pairs and passes each one through as a `--dart-define`.

## Setup

1. Copy the template:
   ```bash
   cp config/dev.json.example config/dev.json
   ```
2. Edit `config/dev.json` with your own values (see the key reference below).
   `config/dev.json` is gitignored — it's local-only and never committed.
3. Run with it:
   ```bash
   flutter run --dart-define-from-file=config/dev.json
   ```

For local mode (the default), you don't need this at all — `flutter run` on
its own already gives you the local/seeded backend with demo surfaces
enabled. This file is mainly useful once you start switching between
`local`/`firebase`/`aws` backend modes regularly, since it saves retyping a
long list of `--dart-define=...` flags every time.

## Key reference

| Key | Values | Default | What it does |
|---|---|---|---|
| `WW_BACKEND_TARGET` | `local` \| `firebase` \| `aws` | `local` | Which repository adapters get built (see `BackendRepositoryBundleFactory`). |
| `WW_APP_ENV` | `local` \| `development` \| `staging` \| `production` | `local` | Cosmetic/readiness-checklist label, shown in Settings → Backend and sync. |
| `WW_CALL_PROVIDER` | `simulated` \| `livekit` \| `twilio` \| `agora` \| `stream` \| `self_managed` | `simulated` | Which calling provider the readiness checklist reports; calling itself is still simulated regardless (see `docs/calling_strategy.md`). |
| `WW_ENABLE_DEMO_SURFACES` | `true` \| `false` | `true` (debug only) | Shows QA-only affordances (e.g. the "QA code: 123456" OTP hint). Always `false` in release builds regardless of this flag. |
| `WW_DEMO_RESTORE_SESSION` | `true` \| `false` | `false` | Auto-restores a seeded demo session at launch, skipping the auth flow entirely. Debug-only, like above. |
| `WW_FIREBASE_PROJECT_ID` | string | `""` | Cosmetic label only — shown in the Backend and sync screen. Does not affect which Firebase project the app actually connects to (that's determined by `lib/firebase_options.dart`, generated by `flutterfire configure`). |
| `WW_USE_FIREBASE_EMULATORS` | `true` \| `false` | `false` | Whether to point at local Firebase emulators instead of live services (once emulator wiring exists). |
| `WW_FIREBASE_OPTIONS_READY` | `true` \| `false` | `false` | Readiness-checklist flag: have you run `flutterfire configure`. |
| `WW_IOS_FIREBASE_CONFIG_READY` | `true` \| `false` | `false` | Readiness-checklist flag: is `GoogleService-Info.plist` in place. |
| `WW_ANDROID_FIREBASE_CONFIG_READY` | `true` \| `false` | `false` | Readiness-checklist flag: is `google-services.json` in place. |
| `WW_FIREBASE_AUTH_READY` | `true` \| `false` | `false` | Readiness-checklist flag: is Firebase Phone Auth wired (yes, as of Slice 2). |
| `WW_FIRESTORE_READY` | `true` \| `false` | `false` | Readiness-checklist flag for Firestore adapters (Slice 3+). |
| `WW_FIREBASE_STORAGE_READY` | `true` \| `false` | `false` | Readiness-checklist flag for Storage-backed media (Slice 4+). |
| `WW_FCM_READY` | `true` \| `false` | `false` | Readiness-checklist flag for push (Slice 5+). |
| `WW_APNS_READY` | `true` \| `false` | `false` | Readiness-checklist flag for iOS push (Slice 5+). |
| `WW_ANALYTICS_ENABLED` | `true` \| `false` | `false` | Readiness-checklist flag for Analytics (Slice 6+). |
| `WW_CRASH_REPORTING_ENABLED` | `true` \| `false` | `false` | Readiness-checklist flag for Crashlytics (Slice 6+). |

Most `*_READY` flags are currently just cosmetic labels surfaced on the
Backend and sync settings screen — they don't gate real behavior yet (that's
intentional scaffolding from `docs/backend_integration_plan.md`, meant to
make "what's actually wired up" auditable at a glance as each slice lands).

`WW_BACKEND_TARGET=firebase` is the one flag that changes real behavior
today — it switches `AuthRepository` from `FakeAuthRepository` to
`FirebaseAuthRepository`.

## Related setup that isn't in this file

Two things `config/dev.json` does **not** cover, because they aren't simple
key/value strings — see `docs/handoff/03_firebase_dev_setup.md` for both:

- The native Firebase config files (`google-services.json`,
  `GoogleService-Info.plist`, `lib/firebase_options.dart`) — generate your
  own with `flutterfire configure`.
- The iOS Phone Auth URL scheme, derived from your own `GOOGLE_APP_ID` — set
  it in `ios/Flutter/Secrets.xcconfig` (copy from `Secrets.xcconfig.example`,
  gitignored, same pattern as this file but on the Xcode side).
